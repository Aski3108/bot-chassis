## 1. Концепция и визуальный стиль (Human-Readable Design)

Настоящий документ является полным описанием требований, макетов экранов и желаемого результата.
**Важное архитектурное разграничение:** данный документ не содержит плана реализации и декомпозиции по гейтам — пошаговый план внедрения формируется отдельной моделью в новом чате.

### Базовые принципы стиля и взаимодействия:
1. **Визуальная чистота и читаемость с первого взгляда:**
   - Самые важные данные, на которые падает взгляд администратора при проверке, выделяются **жирным шрифтом**.
   - Экран чётко разделяется на смысловые блоки **пустыми строками** с логическими подзаголовками.
   - Минимизация «визуального шума»: исключаются избыточные декоративные эмодзи на каждой строке (`📅`, `👑`, `🎁`, `🎟️`, `👥`). Эмодзи допускаются исключительно как функциональные индикаторы состояния (`🟢`, `🔴`, `🛑`, `👤🕶`).
2. **Принцип «Чего нет — того нет»:**
   - Если у пользователя нет роли, подарка, талонов/токенов или рефералов, соответствующие строки **не выводятся вообще**. Никаких строк `Роли: нет`, `VIP Доступ: Отсутствует`, `Талоны: 0 шт.`, `Пригласил рефералов: 0`.
3. **Непрерывность контекста («Stay in Dossier»):**
   - Любое действие администратора в карточке пользователя (бан, разбан, теневой бан, выдача подписки/токенов) обновляет текущее сообщение на месте (`edit_message_text`).
   - Нажатие кнопок действий **никогда не сбрасывает экран**, не снимает кнопки и не отправляет новое главное меню админки в чат. Администратор остаётся в карточке того же пользователя и сразу видит обновлённое состояние.
4. **Строгая иерархия навигации (Канон «Назад» vs «Главное меню»):**
   - **1-й уровень вложенности** от корня админки (Статистика, Поиск, База данных, Рубильник): размещается **строго одна кнопка навигации — `« Назад`**. Кнопка «В главное меню» на этом уровне запрещена как визуальный и логический дубль.
   - **2-й и последующие уровни** (подменю Санкций, подменю Подписок): кнопка `« Назад в досье` возвращает на шаг назад (в базовую карточку этого же пользователя), а кнопка `В главное меню` возвращает сразу в корень админки (`/admin`).
5. **Человекочитаемые карточки вместо сырых логов (Никаких «заплаток экранирования»):**
   - Служебные сообщения (отчёт рамы, аудит бана, лог бэкапа) переверстываются в полноценные аккуратные карточки.
   - Проблема с превращением имени архива в кликабельную web-ссылку из-за доменной зоны `.zip` решается оформлением в аккуратную карточку без вываливания сырых путей и без костыльных заплаток.
6. **Автоматический бэкап включен по умолчанию для файловой SQLite:**
   - Если кузов с постоянным SQLite-файлом не передал политику бэкапа, рама автоматически поднимает штатную политику (04:00 UTC+5). Явный `backup_policy=False`, `:memory:` и SQLite URI с `mode=memory` планировщик не запускают. Убирается необходимость ручного прописывания в коде кузовов и лишние строки статусов планировщика.
7. **Интерактивный ввод с подтверждением (Human in the Loop):**
   - Наложение санкций переводится на безопасный сценарий: запрос причины через сообщение с кнопками мгновенного бана без причины и безопасной отмены.

## 2. Экран «📊 Статистика»

**Статус:** реализовано в 1.0.0 (Gate A6).

### 2.1. Требования к отображению
- Заголовок: `📊 <b>Статистика</b>`.
- Блок аудитории:
  - `Пользователи:` общее число пользователей в БД (жирным).
  - `Новые сегодня:` поднято наверх в блок пользователей.
  - `Активные за 7 дней:` расчёт активных пользователей за последнюю неделю по `last_activity`.
  - `Баны:` объединение обычных и теневых банов в одну понятную строку: общее число банов, а в скобках — сколько из них Shadow.
- Блок финансов и обращений (отделен пустой строкой):
  - `Платежи Stars:` объединённая строка за сегодня и за всё время. Исключить техническую аббревиатуру `XTR`, использовать символ `⭐`.
  - `Gift-подписки:` количество активных на данный момент подарочных подписок.
  - Если есть открытые тикеты поддержки — строка `Открытые обращения: N`.
- Блок системного состояния (отделен пустой строкой):
  - `Последний бэкап:` дата и время последнего успешного снимка.
  - `Рубильник:` статус технического обслуживания (`🟢 снят` или `🔴 включён`).
  - Строка «Планировщик: выключен/включен» исключается: состояние бэкапа отражается строкой последнего успешного снимка, а режим запуска задаётся контрактом `backup_policy`.

### 2.2. Эталонный макет экрана
```html
📊 <b>Статистика</b>

Пользователи: <b>9</b>
Новые сегодня: <b>0</b>
Активные за 7 дней: <b>4</b>
Баны: <b>2</b> (из них Shadow: <b>2</b>)

Платежи Stars: сегодня <b>0 ⭐</b> · всего <b>0 ⭐</b>
Gift-подписки: <b>1</b>
Открытые обращения: <b>0</b>

Последний бэкап: 2026-10-10 04:00 (UTC+5)
Рубильник: 🟢 снят
```

### 2.3. Клавиатура экрана статистики
Строго одна кнопка возврата:
```
[ « Назад ]
```

## 3. Экран «🔍 Найти пользователя» и Список пользователей базы

**Статус:** реализовано в 1.0.0 (Gate A5).

### 3.1. Экран поиска
- Текстовый рудимент `/cancel — отмена` полностью удаляется.
- Администратору предлагается ввести идентификатор либо открыть список всех пользователей базы.

**Макет текста:**
```html
🔍 <b>Поиск пользователя</b>

Отправьте в чат @username или числовой ID пользователя.
Либо откройте полный список пользователей базы данных.
```

**Клавиатура экрана поиска:**
```
[ 👥 Все пользователи базы ]
[ « Назад ]
```

### 3.2. Новый экран «👥 Все пользователи базы» (Просмотр в Telegram)
По нажатию на кнопку `[ 👥 Все пользователи базы ]` бот формирует список пользователей прямо в Telegram-сообщении:
- Нумерованный список: `№. @username (ID) — [Статус/Плашка]`. Если юзернейма нет, выводится только кликабельный ID.
- Плашки статуса справа:
  - `[Суперадмин]` / `[Админ]` — если назначена роль.
  - `[Заблокирован]` — если выдан полный бан.
  - `[Shadow]` — если выдан теневой бан.
  - `[Gift]` — если действует подарочная подписка.
  - Если у пользователя нет специальных статусов, санкций и подарков — плашка не выводится, строка остаётся чистой.
- Пагинация: если пользователей много, выводится ровно по 15 записей на страницу с кнопками пагинации.

**Эталонный макет списка:**
```html
👥 <b>Пользователи базы</b> (всего: <b>9</b>) · Стр. 1/1

1. @Planferno (<code>554750808</code>) — [Суперадмин] [Shadow]
2. @alex_dev (<code>123456789</code>) — [Gift]
3. <code>987654321</code> — [Заблокирован]
4. @maria_k (<code>234567890</code>)
5. @tester_bot (<code>345678901</code>)
```
*(Числовой идентификатор всегда оборачивается в тег <code>ID</code> — при тапе на телефоне он мгновенно копируется в буфер обмена).*

**Клавиатура списка пользователей:**
```
[ 1 ] [ 2 ] [ 3 ] [ 4 ] [ 5 ]   <-- (быстрый переход в досье соответствующей строки)
[ ⬅️ Назад ] [ Вперёд ➡️ ]     <-- (пагинация, только при количестве страниц > 1)
[ « Назад в поиск ] [ В главное меню ]
```
Клик на кнопку `[ N ]` мгновенно открывает карточку досье пользователя из строки `N` без необходимости ручного копирования ID.

## 4. Карточка пользователя («Досье пользователя»)

**Статус:** реализовано в 1.0.0 (Gate A1).

### 4.1. Требования к рендерингу карточки
1. Заголовок: строгий `<b>Досье пользователя</b>` без эмодзи и точек.
2. Имя и идентификаторы: в одной связке `Имя: <b>Имя</b> @username (ID: <code>...</code>)`.
3. Статус выносится наверх, сразу под блоком имени.
4. Разделение типов статусов:
   - Если пользователь активен: `Статус: 🟢 Активен`.
   - Если заблокировал бота сам: `Статус: 🛑 Бот остановлен пользователем`.
   - Если забанен администратором: `Статус: 🔴 Заблокирован`.
   - Если в теневом бане: `Статус: 👤🕶 Теневой бан` (или объединенно `🔴 Заблокирован · 👤🕶 Теневой бан`).
5. Роль: строка `Роль:` выводится **только если назначена** (`Суперадминистратор` или `Администратор`). Обычным пользователям строка роли не пишется вообще.
6. Даты визитов: дата первого визита и дата последнего активного действия (со временем, без избыточных смайликов календаря).
7. Подписка: строка `Подписка:` выводится **только если активна** (`Gift (до YYYY-MM-DD)` или премиум).
8. Токены / талоны: выводятся **только если баланс > 0**.
9. Рефералы: выводятся **только если приглашено > 0 человек**.
10. Полная ликвидация мусорных строк: `Санкции сети` и `profiling: активен` удаляются безвозвратно.

### 4.2. Эталонные макеты карточки досье

#### Вариант 1: Обычный активный пользователь (минималистичный чистый вид)
```html

Имя: <b>Александр</b> @alexander (ID: <code>123456789</code>)

Статус: 🟢 Активен

Первый визит: 2026-10-05 14:20 UTC
Последняя активность: 2026-10-10 12:45 UTC
```

#### Вариант 2: Пользователь с ролью, подпиской, токенами и санкциями
```html
<b>Досье пользователя</b>

Имя: <b>Planferno</b> @Planferno (ID: <code>554750808</code>)

Статус: 🔴 Заблокирован · 👤🕶 Теневой бан
Роль: Суперадминистратор

Первый визит: 2026-10-08 02:59 UTC
Последняя активность: 2026-10-10 15:10 UTC

Подписка: Gift (до 2026-11-08)
Токены: 5 шт.
Рефералы: пригласил 3 чел.
```

#### Вариант 3: Пользователь, заблокировавший бота
```html
<b>Досье пользователя</b>

Имя: <b>Иван</b> @ivan_user (ID: <code>987654321</code>)

Статус: 🛑 Бот остановлен пользователем
```

## 5. Иерархия кнопок досье и интерактивные сценарии

**Статус:** реализовано в 1.0.0 (Gate A1, A2, A3, A4).

### 5.1. Устранение бага сброса экрана
- Обработчики нажатий на кнопки карточки досье исключают вызовы `panels.freeze_as_report` и `_raise_home`.
- Карточка пользователя редактируется на месте через `edit_message_text`. Администратор непрерывно остаётся внутри карточки.

### 5.2. Главная клавиатура карточки досье
Компактные логические группы вместо простыни кнопок:
```
[ 🔴 Санкции (Бан) ]
[ 🎁 Управление подпиской ]
[ « Назад ] [ В главное меню ]
```
*(Кнопка назначения роли Admin исключается из карточки обычного пользователя во избежание случайных нажатий; управление администраторами производится отдельно).*

### 5.3. Подменю «🔴 Санкции (Бан)»
При нажатии на `[ 🔴 Санкции (Бан) ]` клавиатура сообщения переключается:
- Кнопка бана динамически отображает доступное действие:
  - Если пользователь не забанен: `[ 🔴 Выдать бан ]` (ведет на промпт ввода причины §5.4).
  - Если пользователь забанен: `[ 🟢 Снять бан ]` — **срабатывает мгновенно в 1 клик**, без запроса причины разблокировки, обновляет статус в БД, карточка разблокировки сразу отправляется в аудит-чат, а карточка на экране актуализируется.
- Кнопка теневого бана:
  - Если выключен: `[ 👤🕶 Включить теневой бан ]` (ведет на промпт ввода причины §5.4).
  - Если включен: `[ 👤🕶 Снять теневой бан ]` — **срабатывает мгновенно в 1 клик** с отправкой карточки в аудит.
- Нижний навигационный ряд:
```
[ « Назад в досье ] [ В главное меню ]
```
- `« Назад в досье` возвращает кнопки базовой карточки досье (§5.2).
- `В главное меню` возвращает в корень админки `/admin`.

### 5.4. Интерактивный ввод причины бана (Human in the Loop)
При нажатии на `[ 🔴 Выдать бан ]` или `[ 👤🕶 Включить теневой бан ]`:
1. Бот переходит в состояние ожидания ввода причины бана:
```html
⚠️ <b>Блокировка пользователя @Planferno</b> (ID: <code>554750808</code>)

Отправьте в чат причину блокировки:
(или выберите блокировку без указания причины)
```
2. Клавиатура выбора:
```
[ ⚡️ Заблокировать без причины ]
[ ❌ Отмена ]
```
3. Сценарии завершения:
   - Администратор пишет причину в чат (например: `Спам в комментариях`): бот фиксирует причину в БД, отправляет красивую карточку в аудит-чат и возвращает администратора в обновлённое досье пользователя.
   - Администратор нажимает `[ ⚡️ Заблокировать без причины ]`: накладывается бан с дефолтной причиной `Не указана`, отправляется лог в аудит, возврат в досье.
   - Администратор нажимает `[ ❌ Отмена ]`: ожидание сбрасывается, бан не накладывается, экран возвращается в досье пользователя.

### 5.5. Подменю «🎁 Управление подпиской»
При нажатии на `[ 🎁 Управление подпиской ]` клавиатура переключается:
```
[ 🎁 Подарить 30 дней ] [ ♾ Подарить бессрочно ]
[ 🎟 Начислить +1 токен ]
[ 🚫 Отозвать подписку/Gift ]   <-- (отображается только если подписка активна)
[ « Назад в досье ] [ В главное меню ]
```

## 6. Главное меню админки (`/admin`) и раздел «💾 База данных»

**Статус:** реализовано в 1.0.0 (Gate A0, A5).

### 6.1. Очистка главного меню `/admin` и модель безопасности Access Denied
1. Текстовая строка-шпаргалка со списком команд (`Команды: /user · /ban · /unban...`) **полностью удаляется**.
2. Кнопки `📥 Выгрузка базы (Excel)` и `💾 Бэкап базы данных (.db)` убираются с главного экрана и переносятся в отдельный подраздел «💾 База данных».
3. Главная клавиатура администратора:
```
[ 📊 Статистика ]
[ 🔍 Найти пользователя ]
[ 📢 Рассылка ]
[ 💾 База данных ]
[ ⚙️ Рубильник ]
[ 🔄 Рестарт бота ]   <-- (только если доступен ProcessControlPort)
```
4. **Модель контроля доступа («Единая админка с алертом нарушений»):**
   - Меню выводится одинаково для всех администраторов, но операции повышенного риска (`Рассылка`, `База данных`, `Рестарт бота`) требуют прав суперадминистратора (`root`).
   - Если обычный администратор (`staff`, не `root`) нажимает на защищённую кнопку:
     1. Ему на экране показывается всплывающий алерт: **`Access Denied`** (доступ запрещён);
     2. В служебный супер-админский чат (`AUDIT_CHAT_ID` / audit-топик) моментально отправляется security-уведомление:
        `🚨 <b>Попытка несанкционированного доступа</b>: админ @username (ID: <code>...</code>) нажал <b>[Название кнопки]</b>`.

### 6.2. Подраздел «💾 База данных»
По клику суперадмина на `[ 💾 База данных ]` открывается отдельный экран:
```html
💾 <b>Управление базой данных</b>

Выберите действие:
• Выгрузка пользователей — файл Excel (.xlsx) с гиперссылками на профили.
• Бэкап базы данных (.db) — бинарный файл SQLite базы данных проекта.
• Список пользователей — просмотр всей базы прямо в Telegram.
```

Клавиатура подраздела базы данных:
```
[ 📥 Выгрузка пользователей (.xlsx) ]
[ 💾 Бэкап базы данных (.db) ]
[ 👥 Список пользователей в Telegram ]
[ « Назад ]
```
- По клику на `[ 📥 Выгрузка пользователей (.xlsx) ]` или `[ 💾 Бэкап базы данных (.db) ]` файл формируется и сразу отправляется суперадмину в чат (без лишних промежуточных экранов).
- Кнопка `« Назад` возвращает в главное меню админки.

## 7. Автоматические бэкапы по умолчанию в ядре рамы

**Статус:** реализовано в 1.0.0 (Gate A7).

### 7.1. Автоматическая инициализация политики
В фабрике рамы (`src/bot_chassis/factory.py`):
- Если `backup_policy is None` и настроен постоянный файл SQLite, рама автоматически инициализирует штатную `BackupPolicy` (ежесуточно в 04:00 UTC+5, ротация 14 daily / 8 weekly, проверка целостности `PRAGMA integrity_check`).
- Для `:memory:`, пустого пути и SQLite URI с `mode=memory` значение `None` не запускает планировщик.
- Отключение бэкапов возможно только явной передачей `backup_policy=False`.
- Все боты с постоянной файловой SQLite получают автоматические бэкапы из коробки без необходимости правок в коде кузовов.

## 8. Человекочитаемые карточки системных отчётов и аудита

**Статус:** реализовано в 1.0.0 (Gate A7).

Все системные сообщения рамы форматируются как читаемые карточки с жирными ключевыми полями, пустыми строками и без сырых технических хвостов.

### 8.1. Суточный отчёт рамы
Вместо сырого текста с риском кликабельности домена `.zip`, отчёт формируется в виде структурированной сводки с понятными именами ботов:

```html
📋 <b>Суточный отчёт рамы</b>
Период: 2026-10-09 23:30 — 2026-10-10 23:30 (UTC+5)

👥 <b>Аудитория</b>
• Новые пользователи: <b>0</b>
• Живая база (Chat Listener): активных <b>4</b> · остановлено <b>0</b> · удалено <b>0</b>
• Санкции: баны <b>0</b> · теневые <b>0</b>

⭐️ <b>Финансы и поддержка</b>
• Оплаты Stars: <b>0 ⭐</b> (0 шт.) · возвраты: <b>0 ⭐</b>
• Обращения в поддержку: открыто <b>1</b> · закрыто <b>0</b>

💾 <b>Системные задания</b>
• Ночной бэкап: 🟢 успешно (архив: <b>daily_2026-10-10_04-00</b>)
• Ошибки планировщика: <b>0</b> · Ошибки рамы: <b>0</b>
```

### 8.2. Карточка аудита блокировки (`send_admin_audit`)
Вместо нечитаемой строки `Бан user_id=... Причина: — actor=...`:

```html
🚫 <b>Блокировка пользователя</b>

Пользователь: @Planferno (ID: <code>554750808</code>)
Администратор: @admin_username (ID: <code>7891704875</code>)
Тип санкции: <b>Полный бан</b>
Причина: <b>Подозрение на спам</b>
```

### 8.3. Карточка уведомления об автобэкапе
Вместо сырого лога `Backup ok. daily daily_2026-10-10_...zip bytes=8452 by=...`:

```html
💾 <b>Автоматический бэкап базы данных</b>

Статус: 🟢 Успешно (daily)
Архив: <b>daily_2026-10-10_04-00-00_UTC+5</b>
Размер: <b>8.3 КБ</b>
Проект: <b>Chat Listener</b>
```

## 9. Связанные доработки UI, навигации и клиентских экранов рамы (Gate S4 и Live Smoke Profiling)

По решению владельца от 2026-10-11 в общий релиз рамы объединены следующие платформенные задачи:

### 9.1. Находки ручного прогона (Gate S4)

**Статус:** реализовано в 1.0.0 (Gate S4-A, S4-B, S4-C).

1. **S4-A. Маршрут уведомления о старте бота:**
   При запуске/рестарте рама отправляет одно сервисное сообщение в audit destination (`AUDIT_CHAT_ID` / `audit_thread_id`). Если audit-адреса нет — ровно один раз первому суперадмину из `SUPERADMIN_IDS`, без `message_thread_id` и без обхода остальных ID. `SUPPORT_CHAT_ID` не является fallback startup. Остальные служебные каналы сохраняют прежний контракт audit-or-support.
2. **S4-B. Кнопка «Закрыть» на экране истории сообщений тикета:**
   На экране «📜 История диалога» в поддержке добавляется инлайн-кнопка с текстом `Закрыть` (чистый текст без крестиков), удаляющая/закрывающая экран истории.
3. **S4-C. Закрытие экранов рамы при переходе в доменные разделы кузова:**
   При переходе пользователя из служебных разделов рамы (кабинет, FAQ, поддержка) в доменные разделы кузова (опросники PsyBot, витрина Listener и др.), висящие экраны рамы сворачиваются/гасятся через публичный `UserScreenTracker`, доступный как `chassis.screens`.

### 9.2. Находки Live Smoke Profiling

**Статус:** реализовано в 1.0.0 (Gate P1, P2, P3).

1. **P1. Кнопка «Отмена» на экране оплаты (`buy_sku:*`):**
   На платежном инвойсе, который формирует шлюз `src/bot_chassis/payments/router.py`, добавляется каноническая кнопка `Отмена`, чтобы пользователь не застревал на экране оплаты.
2. **P2. Компактный однострочный рендеринг слотов личного кабинета:**
   В `src/bot_chassis/ports/cabinet.py` рендерер слотов кабинета переводится с двустрочного формата `<b>Title</b>\nContent` на компактный однострочный список: `• <b>Title:</b> Content`.
3. **P3. Single-message режим на `/start` (External Track R0):**
   В фабрику добавляется обратно совместимый keyword-only параметр (по умолчанию `False`), позволяющий объединять welcome-текст кузова и нижнюю Reply-клавиатуру рамы в **одно сообщение**, исключая отправку двух сообщений подряд при `/start`.

### 9.3. Статус отложенных направлений

**Статус:** отложено (не входит в Release 1.0).

- **Очередь доставки оплат Listener (`listener-5-2-a-payment-delivery-queue`):** отложена до этапа смока платных тарифов Listener.
- **Ops Sidecar (Node Agent):** отложен до этапа миграции на Linux-сервер. В текущий релиз не входит.
