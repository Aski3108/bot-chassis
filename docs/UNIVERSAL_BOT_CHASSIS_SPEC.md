# Спецификация универсального переносимого шасси бота (Bot Chassis / Universal Bot Skeleton)

**Статус:** Проектная спецификация архитектурного шасси (Core Chassis Architecture)  
**Дата фиксации:** 2026-09-23  
**Целевая платформа:** Экосистема ботов на `aiogram v3` (`Profiling Framework`, `PsyBot`, `Chat Listener` и будущие проекты)  
**Канонический термин:** **«Шасси бота» (Bot Chassis)** — неделимая несущая платформа (транспорт, рантайм-защита, навигация, мост поддержки, платежи), на которую монтируется любой доменный «кузов».
**Цель:** Создание унифицированного, легко переносимого каркаса интерфейса и сервисной обвязки, обеспечивающего 100% одинаковый UX, безопасность и управление данными при минимальных затратах на кастомизацию под конкретный домен.

---

## 1. Терминология: почему именно «Шасси бота» (Bot Chassis)?

В инженерной разработке для такой системы есть несколько терминов, но именно **Шасси (Chassis)** является самым точным:
1. **Шаблон / Boilerplate:** Обычно означает пассивную заготовку кода («скопировал файлы в новую папку и правишь руками»). Шаблон быстро устаревает и расходится на форки.
2. **Ядро / Core:** Термин слишком многозначный (ядро операционной системы, ядро метрик, математическое ядро анализа).
3. **Скелет / Skeleton:** Хороший термин, но ассоциируется со статической структурой папок или черновиком.
4. **Шасси (Chassis):** Идеальная инженерная и продуктовая метафора из автостроения. Шасси — это готовая несущая рама, на которой уже установлены двигатель, ходовая часть, тормоза, рулевое управление и подушки безопасности. На одно и то же шасси можно установить кузов седана (`Profiling Bot`), внедорожника (`PsyBot`) или грузовика (`Chat Listener`), но стандарты управляемости, торможения и безопасности остаются неизменными.

### Core Foundation vs Domain Extensions:
1. **Core Foundation (Шасси — 100% переносимое):**
   - Механика постоянного нижнего меню из 3 кнопок (`[Личный кабинет]`, `[Info]`, `[Поддержка]`).
   - Синяя системная кнопка Telegram «[Меню]» (`set_my_commands`) как гарантия от потери управления.
   - Модуль поддержки **Chat Listener Bridge** (двусторонняя связь пользователь ↔ админ внутри бота с возможностью подключения LLM-оператора 1-й линии).
   - Интерактивный хаб **Info** (методология, FAQ-руководство, взаимная воронка кросс-промо `[Другие проекты]`, переключатель языка `English 🌐`, ссылка на сообщество, правовой дисклеймер 152-ФЗ).
   - **Личный кабинет** (профиль, баланс Telegram Stars, тарифная сетка, статус подписки, ранжированная история сессий/отчетов с кнопками повторного скачивания).
   - **UX-движок:** 3-секундный флеш-экран преимуществ при `/start`, утилита `edit_or_send` с перехватом `message is not modified`, очистка старых экранов (`close_previous_user_screen`), семафор занятости `_user_busy`.
   - **Сессионная гигиена:** RAM-only хранилище сессий ввода (`InMemoryPendingInputStore`) со сбросом при клике на меню — 0 байт на диске, нулевой риск переполнения.
   - **Унифицированная схема PostgreSQL:** `users`, `user_activities_history`, `transactions`, `support_threads`, `reviews`.

2. **Domain Extensions (Проектная надстройка — настраивается конфигом/плагином):**
   - *В Profiling Framework:* вход — файлы JSON/TXT и ссылки на каналы; выход — PDF-отчёты C1–C7, Voiceprint DSL; карточки — монолог / диалог.
   - *В PsyBot:* вход — интерактивные клинические опросники (BAS-18, HCL-32, BPS-20); выход — баллы шкал, интерпретации, кризисные протоколы; кнопки шкал Ликерта (0–3), Panic Button.
   - *В Chat Listener:* мониторинг групп, фильтрация спама, сбор лидов по ключевым словам.

## 3. Граница фиксации костяка (Core Freeze Boundary)

Чтобы разработка не превращалась в бесконечные правки интерфейса под каждый чих, костяк **фиксируется («замораживается»)** на уровне системной платформы:

### Что входит в ЗАФИКСИРОВАННЫЙ костяк (не меняется в проектах):
1. **Транспортная безопасность:** 
   - Неисчезающая клавиатура (`is_persistent=True`, `resize_keyboard=True`).
   - Обязательная регистрация синей кнопки «Меню» в клиенте Telegram через `bot.set_my_commands()`.
   - Защита от потери кнопок при рестартах (`notify_admins_on_startup`).
2. **Рантайм-защита:**
   - Дедупликация повторных кликов пользователя (`ActiveTaskTracker`).
   - Безопасная отмена (`task.cancel()`) устаревшего расчета при смене раздела меню.
   - Автоматический сброс режима ввода текста (`PendingInputStore`) при клике на любую кнопку меню.
3. **UI-гигиена:**
   - Функция `edit_or_send` с перехватом `message is not modified`.
   - Автоматическое закрытие старых экранов (`close_previous_user_screen`) — защита от «кладбища инлайн-кнопок».
   - 3-секундный флеш-экран преимуществ при `/start`.
4. **Коммуникация:**
   - Мост Chat Listener (двусторонняя пересылка сообщений с сохранением медиа через `copy_message` и перехватом блокировок 403 `TelegramForbiddenError`).
5. **Схема данных:**
   - Универсальные таблицы PostgreSQL (`users`, `user_activities_history` с `severity_score`, `transactions`, `support_threads`).

### Что ДОРАЩИВАЕТСЯ поверх костяка индивидуально (Domain Layer):
- Наполнение разделов текстами и карточками через конфиг `bot_config.yaml`.
- Формат и специфика входных данных (файлы, пересылка, опросники).
- Бизнес-логика скоринга и генерации отчетов (PDF C1–C7, клинические опросники, мониторинг чатов).
- Специфические инлайн-кнопки (шкалы Ликерта, выбор режима «Монолог/Диалог»).

### Кнопка 1. `[👤 Личный кабинет]`

#### Логика и экранное сообщение:
- Выдает сводный профиль пользователя прямо из базы данных.
- **Платёжный контур и подписки:**
  - Баланс Stars / внутренняя валюта / рубли.
  - Статус подписки: активна / дата окончания / лимит бесплатных разборов (например: *«Бесплатный скрининг: доступно 1 / 1»*).
  - Тарифная сетка с кнопкой пополнения (`[⭐ Пополнить баланс / Оформить подписку]`).
- **Принцип ранжирования истории:** 
  1. На самом верху — ранее пройденные анализы / тесты с **наибольшей выраженностью** (наивысший процент риска, максимальный балл симптоматики или ключевой профиль), требующие первоочередного внимания.
  2. Ниже — хронологический архив остальных отчётов.
  3. В конце — список доступных, но ещё не пройденных продуктов/тестов платформы.
- **Человеческий язык:** Запрет «птичьего» лабораторного жаргона. Вместо сухих технических аббревиатур (`LTA-001`, `BPS-20`, `BAS-18`) — ясные, понятные формулировки с тематическими эмодзи и процентом выраженности.
- **Идентификация и рефералка:** Telegram ID, дата первого старта, реферальная ссылка с бонусами за приглашение.

#### Пример экрана Личного кабинета:
```text
💼 Личный кабинет

👤 Пользователь: @username (ID: 108234567)
⭐ Баланс: 15 Stars | Подписка: Базовый доступ (до 15.10.2026)
🎁 Доступно бесплатных экспресс-анализов: 1

📊 Ваши ключевые отчёты (ранжированы по выраженности):
🔴 1. Переписка Партнёр ↔ Я (15.09.2026) — Выраженный речевой конфликт (82%)
🟡 2. Канал @my_thoughts (18.09.2026) — Умеренная тревожность (54%)
🟢 3. Тест на СДВГ (10.09.2026) — Низкая выраженность (18%)

💡 Ещё не исследовано вами:
• Исследование переписки двух человек (Диалог)
• Тест на биполярный спектр
```

#### Инлайн-кнопки под Личным кабинетом:
- `[📥 Скачать последний отчёт (PDF)]` *(мгновенная выдача по telegram_file_id)*
- `[📜 Полный архив отчётов]` *(с постраничной пагинацией)*
- `[⭐ Пополнить баланс Stars / Тарифы]`
- `[💬 Задать вопрос по результатам]` *(бесшовный переход в Chat Listener)*

### Кнопка 2. `[ℹ️ Info]` (Научно-методологический хаб + Кросс-промо воронка)

Вместо формальной отписки раздел Info является доказательным фундаментом доверия к сервису и двигателем взаимного трафика во всей экосистеме.

#### Структура разделов:
1. **О проекте и методологии:** 
   - Клинически и математически выверенная структура шкал, концепция многомерного профиля личности без навешивания грубых ярлыков.
   - В PsyBot: на основании чего построены опросники (МКБ-11, DSM-5-TR, валидированные шкалы).
   - В Profiling Framework: психолингвистическая модель, семантические регистры, нормализация на 1000 слов.
2. **«Хейт-трек» (Разбор слепых зон и критика классических методов):**
   - Доказательный крах специфичности устаревших тестов (катастрофа специфичности RAADS-R до 3% в исследовании Jones 2021; сексизм и маскулинный перекос AQ-50; смешение маскинга с травмой fawning в CAT-Q).
   - Почему примитивные детекторы ИИ и поверхностные счётчики дают ложные срабатывания.
3. **FAQ (Инструкция / Руководство пользователя):**
   - Пошаговый графический гайд: как экспортировать чат/канал в JSON или TXT из Telegram Desktop за 3 клика.
   - Как правильно читать радары, оси и графики в PDF-отчёте.
   - Что делать, если балл выраженности высокий (маршрутизация к специалистам).
4. **🚀 Взаимная воронка / Кросс-промо (`[Другие проекты]`):**
   - Все продукты экосистемы одновременно работают воронками взаимного привлечения!
   - Кнопка открывает привлекательную витрину со ссылками на смежные боты:
     - 🧠 **PsyBot** — глубокая клиническая самодиагностика (БАР, СДВГ, депрессия, тревожность).
     - 🔍 **Profiling Bot** — психолингвистический анализ токсичности, скрытых манипуляций и стиля автора.
     - 📡 **Chat Listener** — мониторинг чатов, отслеживание ключевых слов и лидогенерация.
5. **Сообщество и поддержка:**
   - Кнопка `[👥 Чат взаимопомощи / Сообщество]` — ссылка на открытую группу для обсуждения и поддержки.
6. **Правовая информация и дисклеймер:**
   - 152-ФЗ о защите персональных данных: разъяснение, что анализ идёт исключительно в оперативной памяти (RAM) и переписки не сохраняются на диск.
   - Медицинский дисклеймер: сервис не ставит клинических диагнозов и не заменяет очный прием врача-психиатра/психотерапевта.
7. **Переключатель языка (`🌐 English`):**
   - Мгновенная смена языка интерфейса без перезапуска диалога.

### Кнопка 3. `[💬 Поддержка]` (Chat Listener Bridge + LLM-оператор + Отзывы)

Пользователь не должен покидать бота или искать личные контакты создателей. Вся обратная связь замкнута внутри.

#### Архитектура и сценарии:
1. **Двусторонний мост Chat Listener (пользователь ↔ админ):**
   - Пользователь нажимает `[💬 Поддержка]` и видит экран:
     > *«Вы можете написать свой вопрос, пожелание или прикрепить скриншот прямо сюда в чат с ботом. Мы ответим вам прямо в этот диалог.»*
   - Поддерживаются любые типы контента: текст, скриншоты, голосовые сообщения, файлы логов.
   - Сообщение пересылается в закрытый админский чат `SUPPORT_CHAT_ID`.
   - Администратор просто нажимает **«Ответить» (Reply)** на пересланное сообщение в Telegram.
   - Бот перехватывает ответ админа и мгновенно доставляет его пользователю в личку:  
     `💬 Ответ службы поддержки: [Текст / медиа ответа админа]`.
2. **LLM-оператор 1-й линии (AI-саппорт с эскалацией):**
   - Архитектурная готовность: на типовые вопросы из FAQ («как загрузить файл?», «что значит балл 80%?», «как оплатить Stars?») первым отвечает быстрый LLM-оператор по утвержденной базе знаний.
   - Если пользователь пишет сложный нестандартный запрос или нажимает `[👨‍💼 Позвать человека]`, бот мгновенно переключает диалог на живого администратора.
3. **Поддержка проекта (Донаты / Stars):**
   - Кнопка `[⭐ Поддержать проект]` — добровольные пожертвования через Telegram Stars или сторонние платформы (Tribute, эквайринг) на развитие серверов и научных исследований.
4. **Отзывы пользователей (Social Proof):**
   - Кнопка `[✍️ Оставить отзыв]` — сбор обратной связи, пожеланий и оценок сервиса.
   - Кнопка `[⭐ Читать отзывы]` — просмотр проверенных отзывов реальных пользователей прямо в боте.

#### Инлайн-клавиатура под Поддержкой:

## 3. UX-механики взаимодействия и защиты

### А. Синяя системная кнопка «[Меню]» Telegram (`bot.set_my_commands()`)
- **Проблема:** Нижнюю клавиатуру (ReplyKeyboardMarkup) пользователь может случайно свернуть (кнопка с 4 точками в строке ввода) или смахнуть. В этот момент пользователь теряется и считает, что бот «сломался».
- **Решение:**
  - При запуске бот регистрирует команды через Telegram API:
    - `/start` — Перезапуск и главный экран
    - `/menu` — Восстановить главное меню и кнопки
    - `/cabinet` — Личный кабинет
    - `/info` — О проекте, FAQ и экосистеме
    - `/support` — Связаться с поддержкой
  - **Почему это не WebApp:** В Telegram кнопка меню открывает WebApp только в случае специальной регистрации `MenuButtonWebApp`. Стандартная кнопка открывает нативное, мгновенное системное меню Telegram.
  - **Главная ценность:** Синяя кнопка меню **не может исчезнуть никогда** — она зашита в нативный интерфейс клиента Telegram. Даже если пользователь свернул все кнопки, клик по меню мгновенно возвращает его в рабочий режим.

### Б. Хранилище сессий ввода (`InMemoryPendingInputStore`) со сбросом по меню
- **Человеческое объяснение:** 
  - Диск не забьётся **никогда**, потому что на диск пишется ровно **0 байт**!
  - Данные хранятся строго в оперативной памяти (RAM) в виде микро-словаря: `{user_id: {"action": "waiting_support_text", "expires_at": 1720000000}}`.
  - Вес одной сессии — всего около **50 байт**. Даже 100 000 активных пользователей займут меньше 5 мегабайт RAM.
- **Зачем это нужно:**
  - Когда юзер нажал `[✍️ Оставить отзыв]` или `[💬 Поддержка]`, бот ожидает текст сообщения.
  - Если юзер передумал писать отзыв и нажал внизу кнопку `[👤 Личный кабинет]`, бот без этого хранилища посчитал бы слова «👤 Личный кабинет» текстом отзыва и отправил бы админам!
  - `PendingInputStore` отслеживает клик по любой кнопке главного меню, мгновенно стирает ожидание ввода и переключает экран в Личный кабинет.
  - Записи имеют TTL (15 минут): если пользователь закрыл Telegram и ушел, сессия стирается сама по таймеру.

### В. Хелпер `edit_or_send` и автозакрытие старых экранов
- **Проблема «кладбища кнопок»:** Если бот на каждый клик шлёт новое сообщение вниз, чат превращается в бесконечную простыню. Пользователь скроллит наверх, кликает по старым кнопкам трёхдневной давности — бот сыплет ошибками.
- **Решение `edit_or_send`:**
  - Бот аккуратно редактирует текущее сообщение на месте. Экран меняется плавно, как в мобильном приложении.
  - Если Telegram возвращает ошибку `TelegramBadRequest: message is not modified` (например, при двойном быстром клике), хелпер перехватывает её и спокойно гасит — бот не падает.
- **Автозакрытие (`close_previous_user_screen`):**
  - При переходе в новый крупный раздел бот снимает инлайн-клавиатуру с предыдущего экрана или удаляет старое сервисное сообщение. В чате всегда остаётся только один чистый, актуальный экран.

### Г. 3-секундный визуальный флеш-экран при старте (`/start`)
- При нажатии `/start` бот сначала показывает лаконичную карточку преимуществ (3 строки).
- Через 3.0 секунды она бесшовно трансформируется в приветствие с правилами и поднимает нижнюю клавиатуру.

### Д. Семафор занятости `_user_busy`
- Если пользователь отправил тяжелый файл или ссылку на канал, флаг `_user_busy.add(user_id)` блокирует запуск параллельного анализа до завершения текущего.
- При попытке повторного клика бот мягко отвечает: *«Ваш предыдущий анализ уже формируется, пожалуйста, подождите завершения»*.

### Г. Кнопка экстренного выхода («Panic Button / Быстрый выход»)
- *Назначение:* Для деликатных сценариев (анализ токсичных переписок, абьюзивных отношений, кризисных опросников).
- *Поведение:* Закрепленная кнопка `[❌ Быстрый выход]` мгновенно стирает экран переписки и заменяет его нейтральной статьей (погода / рецепт / нейтральный пост), очищая временные FSM-состояния.

### Д. Кризисный протокол («Я в безопасности»)
- *Назначение:* При срабатывании экстремальных маркеров риска (угрозы жизни, суицидальные паттерны).
- *Этический принцип:* **Отказ от блокировки бота на 24 часа.** Бот выводит контакты экстренной психологической помощи и кнопку `[Я подтверждаю, что нахожусь в безопасности]`. После подтверждения анализ продолжается в деликатном терапевтическом ключе.

## 4. Унифицированная схема базы данных (PostgreSQL)

Схема базы данных едина для всех ботов экосистемы:

```sql
-- 1. Пользователи платформы
CREATE TABLE users (
    user_id BIGINT PRIMARY KEY,                      -- Telegram Chat ID
    username VARCHAR(100),
    balance_stars INTEGER DEFAULT 0,                 -- Баланс Stars
    locale VARCHAR(10) DEFAULT 'ru',                 -- Язык интерфейса ('ru', 'en')
    consent_152fz BOOLEAN DEFAULT TRUE,              -- Отметка о принятии правил сервиса
    created_at TIMESTAMP WITHOUT TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITHOUT TIME ZONE DEFAULT NOW()
);

-- 2. Единый реестр активности и отчетов (для Личного кабинета)
CREATE TABLE user_activities_history (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id BIGINT REFERENCES users(user_id) ON DELETE CASCADE,
    title VARCHAR(255) NOT NULL,                     -- Название канала / Имена диалога / Тест
    activity_type VARCHAR(50) NOT NULL,               -- 'monologue_channel', 'dialogue_chat', 'test_bas18'
    severity_score FLOAT DEFAULT 0.0,                -- Балл выраженности (0.0..100.0) для сортировки!
    severity_label VARCHAR(100),                     -- "Выраженный конфликт (82%)", "Норма"
    summary_json JSONB,                               -- Сводка для быстрого превью в кабинете
    telegram_file_id VARCHAR(255),                    -- Идентификатор готового PDF в Telegram для мгновенной переотправки
    created_at TIMESTAMP WITHOUT TIME ZONE DEFAULT NOW()
);
CREATE INDEX idx_user_activities_user_rank ON user_activities_history(user_id, severity_score DESC, created_at DESC);

-- 3. Финансовые транзакции (Telegram Stars / Донаты)
CREATE TABLE transactions (
    transaction_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id BIGINT REFERENCES users(user_id) ON DELETE CASCADE,
    telegram_payment_charge_id VARCHAR(255) UNIQUE,  -- Идемпотентность Telegram Stars
    amount_stars INTEGER NOT NULL,
    transaction_type VARCHAR(50) DEFAULT 'analysis_purchase', -- 'analysis_purchase', 'support_donation'
    status VARCHAR(50) DEFAULT 'COMPLETED',
    created_at TIMESTAMP WITHOUT TIME ZONE DEFAULT NOW()
);

-- 4. Сессии поддержки Chat Listener Bridge
CREATE TABLE support_threads (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id BIGINT NOT NULL,
    admin_chat_id BIGINT NOT NULL,
    admin_message_id BIGINT NOT NULL,                -- ID пересланного сообщения у админа для reply
    user_message_id BIGINT NOT NULL,                 -- ID исходного сообщения пользователя
    status VARCHAR(50) DEFAULT 'OPEN',               -- 'OPEN', 'ANSWERED', 'CLOSED'
    created_at TIMESTAMP WITHOUT TIME ZONE DEFAULT NOW()
);
CREATE INDEX idx_support_reply ON support_threads(admin_message_id);

-- 5. Отзывы и обратная связь пользователей
CREATE TABLE reviews (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id BIGINT REFERENCES users(user_id) ON DELETE CASCADE,
    rating INTEGER CHECK (rating >= 1 AND rating <= 5),
    text TEXT NOT NULL,
    is_published BOOLEAN DEFAULT FALSE,               -- Модерация админом для блока «Читать отзывы»
    created_at TIMESTAMP WITHOUT TIME ZONE DEFAULT NOW()
);
CREATE INDEX idx_reviews_published ON reviews(is_published, created_at DESC);
```

## 5. Файловая структура универсального модуля (`src/bot_core/`)

Модуль оформляется как полностью автономный пакет, подключаемый в диспетчер бота одной строчкой:

```text

├── config.py                 # Загрузка локалей, текстов и эмодзи
├── keyboards/
│   ├── __init__.py
│   ├── main_menu.py          # Постоянная Reply-клавиатура (3 кнопки)
│   ├── cabinet_kb.py         # Инлайн-кнопки Личного кабинета (архив, скачать)
│   ├── info_kb.py            # Инлайн-кнопки Info (English, проекты, статьи)
│   └── support_kb.py         # Инлайн-кнопки Поддержки (Chat Listener, Stars)
├── handlers/
│   ├── __init__.py
│   ├── start_handler.py      # Флеш-экран 3 сек + /start + 152-ФЗ дисклеймер
│   ├── cabinet_handler.py    # Экран кабинета + выдача истории из БД
│   ├── info_handler.py       # Экран Info + «Хейт-трек» + переключение языка
│   └── support_handler.py    # Chat Listener мост (пользователь ↔ админ)
└── utils/
    ├── ui_helpers.py         # edit_or_send, защита от дребезга
    └── concurrency.py        # Семафор _user_busy
```

## 6. Резюме архитектурной ценности
1. **Переносимость между проектами:** Достаточно скопировать папку `src/bot_core/` в любой проект (`Profiling Framework`, `PsyBot`, `Bot 3`), и в новом боте сразу работают: Личный кабинет, Поддержка через личку без ухода из бота, Инфо-хаб со сменой языка и платежи Stars.
2. **Нулевой дубляж кода:** Логика меню, навигации, базы данных и пересылки писем пишется один раз и не переписывается под каждый новый проект.
3. **Безупречный UX:** Отсутствие пугающих юридических простыней, мгновенный отклик, плавная анимация переходов без мигания экрана и защита от перегрузки сервера.
