## 1. Основная клавиатура (Reply Keyboard) и лейблы кнопок

**Статус в `0.3.1`:** реализовано (Gate U1).

### 1.1. Замена «Личный кабинет» на «Аккаунт»
* **Проблема:** На экранах смартфонов 3 кнопки в одну строку (`[Личный кабинет] [Инфо/FAQ] [Поддержка]`) не помещаются по ширине в русской локализации (в отличие от английского `[Account] [Info/FAQ] [Support]`), вызывая перенос на 2 строки или сжатие текста Telegram-клиентом.
* **Решение:** Везде в раме в русском интерфейсе заменить текст кнопки `Личный кабинет` на компактное слово **`Аккаунт`**.

### 1.2. Точная раскладка кнопок и эмодзи основной клавиатуры
* **Русская версия (RU):**
  - `[👤 Аккаунт]` — эмодзи **оставляем** (слово короткое, 7 букв, помещается идеально).
  - `[ℹ️ Инфо/FAQ]` — эмодзи **оставляем**, слэш строго **без пробелов** `Инфо/FAQ`.
  - `[Поддержка]` — эмодзи **убираем** (без эмодзи длинное слово «Поддержка» гарантированно влезает в свою треть экрана).
  - *Итог:* `[👤 Аккаунт] [ℹ️ Инфо/FAQ] [Поддержка]`
* **Английская версия (EN):**
  - Слово `Support` короткое (7 букв), поэтому все три кнопки сохраняют эмодзи:
  - *Итог:* `[👤 Account] [ℹ️ Info/FAQ] [💬 Support]`
* **Внутри экранов (в текстах сообщений):** продолжать использовать полноценное богатое оформление и эмодзи.

## 2. Модуль Техподдержки (Support Bridge)

### 2.1. Сохранение данных заявителя при смене статуса тикета
**Статус в `0.3.1`:** реализовано (Gate S1).
* **Где в коде:** [src/bot_chassis/support_bridge.py:131-180](file:///C:/Python/bot_chassis/src/bot_chassis/support_bridge.py#L131-L180).
* **Проблема (деградация карточки):**
  При создании тикета карточка содержит строку `<b>От:</b> {full_name} ({username})`. Но при нажатии оператором кнопки `[✅ Закрыть обращение]` (или `[🔄 Открыть снова]`) функция `operator_card_text` перерисовывает текст карточки, не зная имени пользователя. В итоге строка с именем и username бесследно исчезает.
* **Решение:**
  1. В структуре тикета `SupportTicket` гарантированно сохранять `full_name` и `username`.
  2. В `operator_card_text(project_label, user_id, status, full_name, username)` выводить строку заявителя **во всех статусах**:
     ```html
     📩 <b>Обращение в поддержку</b>
     <b>Проект:</b> Profiling
     <b>От:</b> Aleksandr (@empatiaradical)
     <b>User ID:</b> <code>7891704875</code>

     <b>Статус:</b> ✅ Обращение обслужено
     ```
  3. Добавить пустую строку перед `<b>Статус:</b>` для визуального разделения.

### 2.2. Ответ службы поддержки пользователю в ОДНОМ сообщении
**Статус в `0.3.1`:** реализовано (Gate S2; режимы `text` / `caption` / `split`).
* **Где в коде:** [src/bot_chassis/support_bridge.py](file:///C:/Python/bot_chassis/src/bot_chassis/support_bridge.py).
* **Проблема:** Сейчас пользователю при ответе оператора приходят два отдельных сообщения подряд:
  1. Шапка: `Ответ службы поддержки:` с кнопкой `Ответить поддержке`.
  2. Второе сообщение: копия текста оператора.
* **Решение:** Если ответ оператора текстовый — объединять его в **одно цельное сообщение**:
  ```html
  💬 <b>Ответ службы поддержки:</b>

  {текст_ответа_оператора}
  ```
  с инлайн-кнопкой `[Ответить поддержке]` под этим же сообщением.

### 2.3. Карточка тикета в чате операторов (объединение текста)
**Статус в `0.3.1`:** **отклонено** владельцем. Ломает Reply-адресацию по копии и дедуп `record_message`. В пакет не входит.
* **Пожелание:** Если сообщение пользователя текстовое, включать текст вопроса прямо в тело карточки тикета оператора (а не слать отдельным `copy_message` снизу), чтобы в чате поддержки не плодились дублирующие сообщения.

### 2.4. Реакция бота (лайк/подтверждение оператору)
**Статус в `0.3.1`:** реализовано ранее и сохранено: после успешной доставки ответа оператору ставится реакция `👍`.
* **Где в коде:** `src/bot_chassis/router.py:706`.
* **Как работает:** Строка `await message.react([types.ReactionTypeEmoji(emoji="👍")])` ставит реакцию `👍` на сообщение оператора в чате поддержки как подтверждение: *«Ответ успешно доставлен пользователю в ЛС»*.
* **Решение:** Механизм задокументирован; реакция оставляется как бесшумный маркер успешной доставки.

### 2.5. Инлайн-кнопка «История переписки»
**Статус в `0.3.1`:** реализовано по метаданным (Gate S3). Тексты сообщений в SQLite **не** заводятся: лента = время, направление, ссылка на сообщение в чате поддержки.
* **Требование:** В карточку тикета для оператора добавить инлайн-кнопку `[📜 История диалога]`, по клику на которую выводится лог последних N сообщений данного пользователя.

## 3. Платформенный канон навигации: «Отмена» vs «Назад»

**Статус в `0.3.1`:** реализовано (Gate U2; card-only `Отмена`).

*Строгое правило для всей платформы (рама bot_chassis и все подключаемые кузова):*

### 3.1. Кнопка «Отмена» — только в КОРНЕ меню
* **Где применяется:** На первом/верхнем уровне любого раздела (`Аккаунт`, `Инфо/FAQ`, `Поддержка`).
* **Логика:** Поскольку пользователь находится в корне раздела, «Назад» нажимать некуда. Поэтому нижняя кнопка называется строго **`Отмена`**.
* **Действие:** Закрывает меню и **всегда гарантированно перерисовывает канонический стартовый экран бота** (через `render_start_callback`), выводя пользователю ключевое приветственное сообщение с инструкциями к продукту. Пользователь никогда не остаётся в пустоте.

### 3.2. Кнопка «Назад» — только ВНУТРИ подэкранов
* **Где применяется:** На любых вложенных экранах (форма «Написать в поддержку», окно доната «Поддержать проект», просмотр конкретной статьи FAQ, экран оплаты).
* **Логика:** Возвращает на 1 уровень вверх — в корень родительского меню (`Поддержка`, `Инфо/FAQ` и т.д.).
* **Правило:** Никаких кнопок закрытия всего окна с потерей контекста из вложенных подэкранов — строго **`Назад`**.

### 3.3. Кнопки внутри раздела Поддержки
* На инлайн-кнопках меню убрать эмодзи:
  - `Написать в поддержку` (без лишних значков)
  - `Поддержать проект` (без сердечка)
* Внутри самих открытых экранов сохранить полноценное форматирование с эмодзи.

## 4. [ИССЛЕДОВАНИЕ / ВЫЧИСТКА ХАРДКОДА] Языки и локализация

### 4.1. Разбор бага со скриншота (кейс PsyBot / tg_psy_tests)
**Статус в `0.3.1`:** **не в этом репозитории.** Handoff в чат PsyBot (`C:\Python\tg_psy_tests`). Из корня рамы не делается.
* **Суть проблемы:** Вместо переименования старой кнопки смены языка была создана новая кнопка в раме, а старая осталась в коде кузова PsyBot. В итоге:
  1. На стартовом экране вылезали две конкурирующие кнопки: `[Language / Язык]` и `[🌐 Русский / English]`.
  2. Старая кнопка `Language / Язык` осталась пристёгнутой к каждому экрану вопроса опросника (в `psybot/handlers/user.py:689` и YAML).
* **Требуемые действия по очистке кодовой базы PsyBot (`C:\Python\tg_psy_tests`):**
  - Полностью вырезать старую кнопку `Language / Язык` из генератора вопросов опросника (`user.py:689`).
  - Удалить дублирующую кнопку со стартового экрана, оставив единственный централизованный переключатель рамы.
  - Устранить «заплаточный» подход: при внедрении новой механики старая реализация должна удаляться, а не накрываться сверху новой.

### 4.2. Правило для кузова Profiling Framework
**Статус в `0.3.1`:** уже поддержано конфигурацией `enable_language_switch=False`; изменений кода рамы не требуется.
* Так как в `Profiling_Framework` все 12 контуров анализа и психолингвистические карточки формируются на русском языке, фиктивный переключатель языков рамы отключается через конфигурацию (`enable_language_switch=False`), чтобы не вводить пользователя в заблуждение переключением только одного лейбла на кнопке.
